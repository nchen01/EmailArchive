# S17.2 — Handoff Package Domain-Model & API Spec (read-only draft)

**Status:** 📝 Spec draft for product review — **docs only, no implementation**.
No migrations, Pydantic/SQLAlchemy models, API routes, or frontend are written in
this ticket. Everything below is at the *specification* level for approval before
S17.3+ coding begins.

**Decision source:** D14 (`docs/decisions.md`); resolved product questions in
`docs/s17-handoff-package-mvp-plan.md` §8a. Where §8a resolved a question, this
spec treats it as binding.

---

## 1. Purpose & framing

A **handoff package** is an employee-initiated, audited, scoped continuity
artifact. The covered employee creates it, chooses scope, reviews what will be
revealed, prunes it, and publishes a **read-only, package-scoped** view to one
coverage recipient. The recipient reads cited evidence *inside the package* — not
the mailbox.

Two distinct surfaces, deliberately different:
- **Creator scope review** (pre-publish, the employee's *own* mailbox): full
  inspection, aggregate exclusion counts, and the existing S11–S14 source
  navigation (including the S14 "Search in Gmail" affordance over their own
  mail). This is the *pruning* surface.
- **Recipient package view** (post-publish): read-only, snapshotted, package-
  scoped. Global privacy posture only; **no** exclusion counts, **no** Gmail
  link, **no** raw mailbox, **no** live queries beyond package evidence.

The S11–S14 evidence drawer / Gmail-link code is retained for the creator surface
and is **explicitly not the recipient model** (§8a-6, marked *changeable*).

## 2. Where the objects live (resolves S17.2's open sub-question)

**Recommendation:** handoff objects are **product/API-layer**, not pipeline
contracts. Implement them as **SQLAlchemy ORM tables** (`services/db/models.py`)
+ **API DTOs** (`services/api/schemas/`). Do **not** add them to
`packages/ekc_schemas/` — that package is the L0–L3 pipeline contract (Message,
Person, Project, Event…), and handoff packages are a surface built *on top* of it.
Consequently **`SCHEMA_VERSION` is not bumped** by S17 (no `ekc_schemas` change).

## 3. Domain objects (spec-level tables)

IDs are UUIDv4 (repo convention). Provenance/citation keys are
`Message.message_id_header` (RFC 5322), never internal UUIDs (AGENTS §3). All
tables are `mailbox_id`- or `package_id`-scoped.

### 3.1 `handoff_package`
The lifecycle root. One row per version (see §6 versioning).

| Field | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `mailbox_id` | UUID FK→mailbox | the covered employee's mailbox |
| `creator_email` | text | the covered employee (owner) |
| `creator_person_id` | UUID FK→person, null | resolved owner identity when known |
| `status` | text enum | `draft`→`generated`→(`submitted`→`approved`→)`published`→{`expired`\|`revoked`\|`superseded`}. `submitted`/`approved`/`rejected` **reserved** (approval deferred, §8a-1) |
| `reason` | text enum | `vacation`\|`leave`\|`transfer`\|`delegation`\|`other` (audit metadata only; never an employment signal) |
| `title` | text | |
| `policy_mode` | text | `standard` (only value in MVP; reserves elevated modes) |
| `version` | int | 1-based; increments per superseding version (§6) |
| `supersedes_package_id` | UUID FK→handoff_package, null | prior version in the lineage |
| `lineage_id` | UUID | stable across versions (all versions of one handoff share it) |
| `created_at` / `updated_at` | timestamptz | |
| `published_at` | timestamptz, null | set on publish; freezes the package |
| `expires_at` | timestamptz, null | default `published_at + 30d`, adjustable (§8a-3) |
| `revoked_at` | timestamptz, null | |

### 3.2 `handoff_scope`
1:1 with a package. What the creator selected. MVP uses Postgres arrays;
join-tables are the scale path (non-blocking).

| Field | Type | Notes |
|---|---|---|
| `package_id` | UUID FK, **unique** | 1:1 |
| `date_from` / `date_to` | date, null | inclusive window (reuses S16.0 `ListOptions` semantics) |
| `included_project_ids` | UUID[] | |
| `included_person_ids` | UUID[] | |
| `included_thread_ids` | UUID[] | |
| `excluded_thread_ids` | UUID[] | creator-pruned |
| `excluded_message_id_headers` | text[] | creator-pruned |
| `allowed_domains` | text[] | optional people/domain narrowing |
| `keyword_filters` | text[], null | optional |

### 3.3 `handoff_recipient`
Exactly **one per package** in MVP (§8a-2), enforced by a unique constraint on

| Field | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `package_id` | UUID FK, **unique (MVP)** | |
| `recipient_email` | text | |
| `recipient_person_id` | UUID, null | |
| `access_token_hash` | text | store a **hash** only; the raw token lives only in the share link |
| `granted_at` | timestamptz | |
| `expires_at` | timestamptz | mirrors package `expires_at` |
| `revoked_at` | timestamptz, null | |
| `last_accessed_at` | timestamptz, null | |

### 3.4 `handoff_claim`
**Proposed addition** (beyond the six planning names). The recipient view shows
*cited claims* (briefing lines, project state, open loops, decisions, blockers).
`handoff_evidence` already references "included claim IDs", so a claim object is
required to satisfy **no citation, no claim** inside the package. Flagged for
product ack (§9).

| Field | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `package_id` | UUID FK | |
| `kind` | text enum | `briefing`\|`project_state`\|`open_loop`\|`decision`\|`blocker`\|`person_note` |
| `text` | text | synthesized statement (L3 output, snapshotted at publish) |
| `project_id` | UUID, null | |
| `source_message_id_headers` | text[] | **≥1** (invariant); each must resolve to `handoff_evidence` in this package |
| `confidence` | numeric | display-gated like L1/L3 |

### 3.5 `handoff_evidence`
**Snapshotted at publish** from the safe subset of included messages. Immutable
thereafter. This is what the recipient reads — no live-mailbox dependency.

| Field | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `package_id` | UUID FK | |
| `message_id_header` | text | citation key (unique per package) |
| `subject` | text | MIME-decoded snapshot |
| `sender_display` / `sender_domain` | text | safe sender fields (S14 rules) |
| `ts` | timestamptz | |
| `body_snapshot` | text | normalized, sensitivity-gated `clean_text`, bounded (default 2000 chars; conservative rec §9) |
| `source_type` | text enum, null | `l1_structured`\|`l2_retrieval` |
| `snapshotted_at` | timestamptz | = publish time |

**Invariant:** a row exists here **only** if its message passed the whole-thread
sensitivity gate (S14/S9) **and** was not creator-excluded. Sensitive/excluded
content never enters this table.

### 3.6 `handoff_exclusion`
**Creator/audit-only.** Records what was withheld and why. **Never exposed to the
recipient** (the recipient sees only a global posture, §8a-5). For sensitivity
exclusions, the target reference is retained for the creator/audit but is not a
per-topic oracle to the recipient.

| Field | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `package_id` | UUID FK | |
| `exclusion_type` | text enum | `sensitivity`\|`user_removed`\|`policy_removed`\|`duplicate`\|`low_confidence` |
| `target_type` | text enum | `message`\|`thread`\|`project`\|`person`\|`claim` |
| `target_ref` | text | id or `message_id_header`; creator/audit scope only |
| `aggregate_label` | text | e.g. "sensitivity" — the only granularity a creator UI groups by |
| `audit_reason` | text, null | free text, no message body |
| `created_at` | timestamptz | |

### 3.7 `handoff_audit_event`
**Append-only**, dedicated table (mirrors the existing `audit_log` retention
rule: no FK cascade; rows survive package revocation/deletion). Package-scoped.

| Field | Type | Notes |
|---|---|---|
| `id` | bigint PK | |
| `package_id` | UUID (no FK cascade) | retained after revoke/delete |
| `lineage_id` | UUID | cross-version trail |
| `actor` | text | `owner:<email>`, `recipient:<token_hash_prefix>`, or `system` — never a raw token |
| `action` | text enum | see §5 vocabulary |
| `ts` | timestamptz | |
| `metadata` | JSONB | **safe only**: counts, ids, status — **no** body text, subject text, snippet, token, or secret |

## 4. State model

### 4.1 Transitions
| From | Event | To | Notes |
|---|---|---|---|
| — | create | `draft` | creator only |
| `draft` | set scope | `draft` | |
| `draft` | generate | `generated` | candidate built (not yet frozen) |
| `generated` | re-scope / exclude | `generated` | still mutable |
| `generated` | publish | `published` | **freezes**: snapshots evidence+claims, sets recipient/token/`expires_at` |
| `generated` | submit *(reserved)* | `submitted` | approval path, deferred |
| `submitted` | approve/reject *(reserved)* | `approved`/`draft` | deferred |
| `approved` | publish *(reserved)* | `published` | deferred |
| `published` | time ≥ `expires_at` | `expired` | recipient access blocked |
| `published` | revoke | `revoked` | recipient access removed; audit kept |
| `published` | new version published | `superseded` | recipient access moves to the new version |

Reserved states (`submitted`, `approved`, `rejected`) exist in the enum now so the
approval path (S17.8) adds no migration (§8a-1).

### 4.2 Terminal/blocked access
`expired`, `revoked`, and `superseded` all **block recipient reads** (return a
neutral "this handoff is no longer available"); audit rows remain.

## 5. Audit vocabulary & safe metadata

Actions: `handoff_created`, `scope_changed`, `candidate_generated`,
`evidence_excluded`, `package_submitted` *(reserved)*, `manager_approved` /
`manager_rejected` *(reserved)*, `package_published`, `recipient_viewed`,
`evidence_opened`, `package_asked` (recipient Cover-for-me), `package_expired`,
`package_revoked`, `version_superseded`.

**Safe to store in `metadata`:** counts (e.g. `{included_evidence: 42,
excluded_sensitivity: 12}`), object ids, `message_id_header` values (they are
citation keys, not content), status, recipient email, expiry timestamps.
**Never store:** message bodies, subjects, snippets, OAuth/access tokens, or raw
exception text (mirrors the S16 audit discipline).

## 6. Versioning & immutability

- **Publish freezes** the package: `handoff_scope`, `handoff_evidence`, and
  `handoff_claim` become immutable for that `id`.
- To change a published package, the creator issues **new version**: a new
  `handoff_package` row with `version+1`, `supersedes_package_id = old.id`, same
  `lineage_id`, status `draft`. It is re-scoped/re-generated and re-published.
- On the new version's publish: the old version → `superseded`; the recipient's
  access (token) is **rotated to the latest published version in the lineage**
  (old token revoked, new token issued and re-shared). The recipient always sees
  exactly one live version.
- Superseded versions are recipient-blocked but retained for audit.

## 7. API surface (spec-level only)

**Creator endpoints** — authenticated as the mailbox owner (reuse existing owner
auth context). Never expose another mailbox.

| Method & path | Purpose |
|---|---|
| `POST /api/handoff/{mailbox_id}` | create draft (`reason`, `title`) |
| `PATCH /api/handoff/{package_id}/scope` | set/update scope (draft/generated only) |
| `POST /api/handoff/{package_id}/generate` | build candidate (project summaries, claims, evidence preview) over safe scope |
| `GET /api/handoff/{package_id}` | creator review view: included projects/people/claims/evidence **+ aggregate exclusion counts** |
| `POST /api/handoff/{package_id}/exclude` | remove message/thread/project/person/claim → writes `handoff_exclusion` + audit |
| `POST /api/handoff/{package_id}/publish` | freeze+snapshot; set recipient, `expires_at`; issue token; status→`published` |
| `POST /api/handoff/{package_id}/revoke` | status→`revoked`; remove recipient access |
| `POST /api/handoff/{package_id}/new-version` | create a superseding draft from a published package |

**Recipient endpoints** — authenticated by the **package access token**, not a
mailbox. All are package-scoped and block on `expired`/`revoked`/`superseded`.

| Method & path | Purpose |
|---|---|
| `GET /api/handoff/recipient/{token}` | package view: briefing, projects, people, claims, evidence, **global privacy posture** (no counts) |
| `POST /api/handoff/recipient/{token}/ask` | package-scoped Cover-for-me — citation allow-list **restricted to this package's `handoff_evidence`** |
| `GET /api/handoff/recipient/{token}/evidence/{message_id_header}` | snapshotted source detail **from `handoff_evidence`** (no Gmail link, no live mailbox) |

Every recipient call writes `recipient_viewed` / `evidence_opened` /
`package_asked`. The recipient `ask` reuses L3 synthesis but the allow-list is the
package evidence set, which is exactly what makes it package-scoped **and** keeps
the no-existence-oracle guarantee (a sensitive/unknown question returns the same
no-evidence response as S14).

## 8. Invariants (must hold in implementation)

1. **No raw mailbox for recipient.** Recipient endpoints read only
   `handoff_*` rows for their package; they never touch `message`/`thread`/etc.
2. **No sensitive/excluded evidence in `handoff_evidence`.** The publish snapshot
   applies the whole-thread sensitivity gate and the creator exclusion set;
   anything failing either never lands in the table.
3. **No citation, no claim (package-local).** Every `handoff_claim` has ≥1
   `source_message_id_headers`, each resolving to `handoff_evidence` in the same
   package. Claims with no in-package evidence are dropped.
4. **No existence oracle.** Recipient sensitive-only and unknown questions return
   the identical no-evidence response (S14); the recipient never receives
   exclusion counts or per-topic exclusion info.
5. **No performance/productivity use.** No scores, metrics, rankings, sentiment,
   effort/responsiveness, or "what did they do all day" anywhere in these objects
   or endpoints.
6. **Immutability after publish.** Frozen scope/evidence/claims; change = new
   version.
7. **Auditability.** Every mutation and every recipient access writes a
   `handoff_audit_event` with safe metadata only.
8. **Expiry + revocation.** Recipient access is time-bounded and revocable;
   blocked states return a neutral message and retain audit.
9. **One recipient (MVP).** Unique `package_id` in `handoff_recipient`.

## 9. Open questions (conservative recommendations; none blocking)

1. **`handoff_claim` as a first-class object?** *Recommend yes* — the recipient
   view needs cited claims and evidence already references claim ids. (Only item
   that expands the six planning names; flagged for explicit product ack.)
2. **Recipient auth = capability token in the share link.** *Recommend yes* for
   MVP (hashed at rest, expiring, revocable). Account-based recipient auth is a
   later hardening.
3. **Body snapshot length.** *Recommend* a bounded `body_snapshot` (default 2000
   chars of normalized `clean_text`) rather than full bodies, tunable later.
4. **Scope storage: arrays vs join tables.** *Recommend arrays* for MVP;
   migrate to join tables only if scope sizes or query needs demand it.
5. **Claim generation source.** *Recommend* reusing existing L1/L3 outputs
   (project summaries, events, cover-for-me synthesis) over the package scope at
   `generate`, then freezing at `publish`. No new synthesis algorithm (per S17 §9).

## 10. Acceptance criteria for implementation (S17.3+)

- One Alembic migration creates all `handoff_*` tables; `SCHEMA_VERSION`
  unchanged (no `ekc_schemas` edit).
- Package lifecycle enforces the §4 transitions; illegal transitions rejected.
- `publish` snapshots evidence + claims and enforces post-publish immutability;
  editing a published package is only possible via `new-version`.
- The publish snapshot provably excludes sensitive (whole-thread) and
  creator-excluded messages; a test asserts no excluded `message_id_header`
  appears in `handoff_evidence`.
- Recipient endpoints reject `expired`/`revoked`/`superseded`, never return
  non-package data, expose no exclusion counts, and offer no Gmail/live link.
- Recipient `ask` restricts the citation allow-list to package evidence and
  preserves the S14 no-existence-oracle behavior (tested).
- Every mutation/access writes a `handoff_audit_event`; a test asserts no body/
  subject/snippet/token appears in audit `metadata`.
- One-recipient constraint enforced; expiry default = `published_at + 30d`,
  per-package override honored.
- Creator review still uses the S11–S14 drawer (incl. own-mailbox Gmail link);
  recipient uses the package view only — a test asserts the two surfaces differ.

## 11. Relationship to existing work

- **S11–S14** evidence/source-navigation → the **creator** inspection + pruning
  surface (not the recipient model).
- **S16.0** date-range ingest → the ingest primitive under package scope
  (`handoff_scope.date_from/date_to` reuse `ListOptions`).
- **S16.1** demo fixture → authored to demonstrate the create→scope→review→publish
  →recipient flow for **vacation coverage** (§8a-7).
- Core clustering/retrieval/synthesis algorithms are **unchanged** (S17 §9).
